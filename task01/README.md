# Задание 01 Lucky (Задача 11.1)

## Условие

Программа при каждом запуске выводит разные результаты, необходимо разобраться из-за чего это происходит и исправить программу так, чтобы она выводила правильный результат.

Убедитесь, что потоки работают параллельно и блокируют друг друга минимально возможное время.

## Исходный код

```java
public class Lucky {
    static int x = 0;
    static int count = 0;

    static class LuckyThread extends Thread {
        @Override
        public void run() {
            while (x < 999999) {
                x++;
                if ((x % 10) + (x / 10) % 10 + (x / 100) % 10 == (x / 1000)
                        % 10 + (x / 10000) % 10 + (x / 100000) % 10) {
                    System.out.println(x);
                    count++;
                }
            }
        }
    }

    public static void main(String[] args) throws InterruptedException {
        Thread t1 = new LuckyThread();
        Thread t2 = new LuckyThread();
        Thread t3 = new LuckyThread();
        t1.start();
        t2.start();
        t3.start();
        t1.join();
        t2.join();
        t3.join();
        System.out.println("Total: " + count);
    }
}
```

## Анализ проблемы

1. **Состояние гонки (Race condition) на переменной `x`**: операция `x++` не атомарна (состоит из чтения, инкремента и записи). Потоки перезаписывают значения друг друга, пропускают билеты или проверяют одни и те же числа повторно.
2. **Выход за границы диапазона**: проверка `while (x < 999999)` выполняется без синхронизации с инкрементом. Если несколько потоков проверят условие при `x == 999998`, они все зайдут в цикл и увеличат `x` до 999999, 1000000 и 1000001 (числа с более чем 6 знаками).
3. **Потеря обновлений на переменной `count`**: `count++` также не атомарен, что приводит к утере подсчитанных счастливых билетов.
4. **Неактуальное значение при выводе**: `System.out.println(x)` может напечатать не то число, которое проверялось в `if`, если другой поток успел изменить `x`.

## Решение

- Используются отдельные объекты синхронизации (`xLock` и `countLock`) для критических секций получения следующего числа и увеличения счётчика.
- Проверка границы (`x >= 999999`) и инкремент производятся атомарно в блоке `synchronized (xLock)`, значение сохраняется в локальную переменную `currentX`.
- Вычисление суммы цифр и проверка условия "счастливого билета" производятся **вне критической секции**, что обеспечивает параллельное выполнение тяжелых вычислений всеми потоками.
- Общее количество счастливых билетов в диапазоне 1..999999 всегда стабильно и равно **55251**.
